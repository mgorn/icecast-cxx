# Architecture guidance

`icecast-cxx` is a modern C++ client-facing networking/protocol library for Icecast. It is not a wrapper around Icecast server-global structures and it is not an audio engine.

## Implemented layers

- `icecast::core` — common value models, URLs/mountpoints, credentials, headers, structured errors/results, capabilities.
- `icecast::stream` — transport-independent listener/publisher models, state, reconnect policy, encoded-byte backpressure, ICY demultiplexing.
- `icecast::transport_curl` — native listener HTTP/HTTPS implementation using libcurl.

Planned separable layers include `icecast::admin`, `icecast::publish_libshout`, and `icecast::transport_web`.

## Media boundary

Listening:

```text
Icecast -> encoded bytes -> icecast-cxx -> caller decoder/demuxer -> decoded media
```

Publishing:

```text
caller source -> caller encoder/muxer -> encoded bytes -> icecast-cxx -> Icecast
```

Keep codec encode/decode, PCM processing, audio devices, sample conversion, media graphs, general container demux/mux, and media-file pacing outside this project. ICY framing is an Icecast stream concern and belongs in `stream`; container-native metadata remains encoded media.

## Public type philosophy

Prefer value-oriented `struct`s for configuration, metadata, status, and results. Avoid public virtual transport hierarchies.

Active resource-owning network/session types are the deliberate exception to the open-data style: their implementation state may be opaque to preserve invariants and backend isolation. Do not expose `CURL*`, `shout_t*`, browser JS handles, or equivalent implementation state.

## Listener semantics

A listener represents one logical listening session and delivers encoded bytes, normalized stream info, optional ICY metadata, lifecycle changes, and structured errors.

Borrowed byte spans are callback-scoped. Backpressure is explicit. Buffering must be bounded. Every successful physical connection increments the connection generation so a caller can reset decoder/container state after reconnect.

Automatic listener reconnect is a first-class policy.

## Publisher semantics

A publisher receives already encoded/muxed bytes from the caller. It must expose bounded backpressure and must not silently drop media.

Do not blindly reconnect a source and continue from the middle of the previous logical encoded stream. A new physical publication may require fresh container headers generated by the caller.

## Native vs browser networking

Native HTTP uses libcurl behind `icecast::transport_curl`. Browser/WebAssembly transport will use browser networking semantics rather than pretending POSIX sockets are available.

Platform/server/effective capabilities should expose meaningful environmental differences instead of scattering platform checks through application code.

## Execution model

Native progress is explicitly caller-driven. `curl_context::poll()` is the current native execution mechanism; it creates no hidden networking thread and invokes callbacks on the polling thread.

Do not introduce a global thread pool, thread-per-stream design, or custom coroutine runtime without a separate architecture decision.

## Errors

Operational failures are structured values. Backend numeric codes can be diagnostics but do not define the public error taxonomy.

## Python

The future `pycecast` project will bind this C++ API separately, likely through pybind11. Do not add Python dependencies or deform the C++ API around Python-specific concerns.
